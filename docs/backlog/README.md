# Backlog

One markdown file per ticket, versioned with the code. `INDEX.md` is generated —
never edit it by hand.

## Files

```
NNN-short-slug.md    a ticket; NNN must match its `id:` field
TEMPLATE.md          copy this to start a new one
INDEX.md             generated by `npm run backlog`
```

## Frontmatter

Every ticket starts with exactly these five fields:

```yaml
---
id: 002
title: markReminderDone never advances nextDueDate
status: open
priority: P1
type: bug
---
```

| Field | Allowed values |
| --- | --- |
| `id` | Three digits, unique, never reused. The filename must start with `<id>-`. |
| `title` | One line, imperative or descriptive. No trailing period. |
| `status` | `open` · `in-progress` · `blocked` · `done` |
| `priority` | `P0` broken or unsafe in production · `P1` real user-visible defect · `P2` correctness or maintainability · `P3` cleanup |
| `type` | `bug` · `security` · `refactor` · `feature` · `chore` · `docs` |

`npm run backlog:check` runs in `npm run verify` and in CI. It fails on a missing
field, an invalid value, a duplicate id, a filename that disagrees with its id, or
an `INDEX.md` that no longer matches the tickets.

## Body

Four sections, in this order. Keep each short.

- **Problem** — what is wrong, with file and line references.
- **Why it matters** — the observable consequence. If there isn't one, reconsider
  the ticket.
- **Acceptance criteria** — checkboxes a reviewer can verify without reading your
  diff.
- **Notes** — constraints, prior decisions, related tickets. Optional.

## Lifecycle

`open` → `in-progress` (when you start) → `done` (when merged). Done tickets stay
in the repo as history; they are not deleted.

`blocked` means something outside the repo has to happen first — name it in
**Notes**.

Closing a ticket that is only partly done is not allowed: split it, and say in the
new ticket what was left behind.
